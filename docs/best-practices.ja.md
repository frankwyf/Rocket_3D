# Rocket 3D ベストプラクティス改善ガイド（体系版）

本ドキュメントは C++17 のリアルタイム可視化/ゲーム系プロジェクトで有効な実践を、本リポジトリ向けに整理したものです。

## 1) アーキテクチャと責務分離

- **レンダリング**、**ゲームロジック**、**入力処理**を分離する。
- OpenGL コンテキスト不要の純粋ロジックを増やし、単体テストを容易にする。
- ミッション判定ロジックを描画 API 実装から独立させる。

## 2) データ駆動のゲーム設計

- レベル/チャレンジ値は配列や JSON で管理し、ハードコード分岐を減らす。
- バランス調整パラメータを集約して管理する。
- テレメトリ/スコア処理は独立検証可能な形にする。

## 3) 可視化分析と観測性

- 高度・速度・燃料の短周期テレメトリを記録する。
- スパークラインやリスク色などの軽量オーバーレイで調整を高速化する。
- データ生成と描画処理は分離し、再利用性を高める。

## 4) テスト戦略（C++17）

- まずゲームロジック/ユーティリティを優先的にテストする。
- UI ヒットテストの境界ケースを追加する。
- リスク計算、状態遷移、効果期限切れを検証する。
- テスト実行バイナリはゲーム本体から独立させる。

## 5) CI/CD 品質ゲート

- `Debug` と `Release` を両方ビルド/テストする。
- `JUnit XML` を出力して機械処理可能にする。
- GitHub Actions で行カバレッジを収集する。
- カバレッジ下限を設定して品質低下を防ぐ。
- バイナリ/テスト結果/カバレッジ XML をアーティファクト化する。

## 6) 実施順序

1. テスト可能なゲームロジック/テレメトリを追加
2. 単体テストと境界テストを追加
3. ローカルで Debug/Release を検証
4. CI 行列とカバレッジワークフローを導入
5. テスト充実に合わせて閾値を段階的に引き上げ

## 7) GitHub Actions 確認項目

- `CI` の行列ジョブがすべて成功
- `Coverage` の閾値チェックが成功
- 次のアーティファクトが取得可能
  - テストレポート
  - カバレッジレポート（`coverage.xml`）
  - 実行ファイル
